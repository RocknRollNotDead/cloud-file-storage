Тут расскажу как я деплоил несколько сервисов сразу, как на codeportfolio.ru

Начну с того, сервер Beget у меня слабенький - 1 гб оперативки и 10 гб внутренней памяти.
Поэтому у меня не могли скачаться не только параллельно зависимости из разных сервисов, но иногда и зависимости из одного сервера.
поэтому я перешёл на такую тактику - дома собираю докер образы программ и отправляю их на сервер, и там композирую уже из собранных образов программ.
Без этого легкие программы в параллель без снятого флага BUILDKIT не загружаются и стопарятся, а средние по весу программы и со снятым флагом не загружаются.

Всё что нужно на сервере - докер.

1. Образы
Первый образ - несколько программ на томкате. 
Пишем докерфайл для нескольких програм (у меня это 3 и 4 проект роадмапа). 2 билд секции, и одна для запуска томката, где мы просто копируем собранные war файлы в образ томката.
За счёт этого можно создать много путей. У меня это "/", "/exchange" и "/tennis". / путь это index.html, который я просто положил в томкатовскую папку root, где он ищет статику.

```Dockerfile

FROM maven:3.9-eclipse-temurin-21 AS build-tennis
WORKDIR /project
COPY tennis-match-scoreboard/pom.xml .
RUN mvn dependency:go-offline
COPY tennis-match-scoreboard/src ./src
RUN mvn clean package -Dmaven.test.skip=true

FROM maven:3.9-eclipse-temurin-21 AS build-exchange
WORKDIR /project
COPY currency-exchange/pom.xml .
RUN mvn dependency:go-offline
COPY currency-exchange/src ./src
RUN mvn clean package -Dmaven.test.skip=true

FROM tomcat:10-jdk21
RUN rm -rf /usr/local/tomcat/webapps/ROOT
COPY root/ /usr/local/tomcat/webapps/ROOT/
COPY --from=build-tennis /project/target/*.war /usr/local/tomcat/webapps/tennis-match-scoreboard.war
COPY --from=build-exchange /project/target/*.war /usr/local/tomcat/webapps/currency-exchange.war
EXPOSE 8080
CMD ["catalina.sh", "run"]
```
Однако чтобы это всё было по одному порту, то есть по одному домену, нужно все 3 директории `tennis-match-scoreboard currency-exchange root` 
запихнуть в одну папку, где будет докерфайл.

Второй образ - одна программа на одном образе.
Спринг бут проект под капотом уже имеет свой томкат, поэтому на один образ запихнуть несколько путей независимых программ нельзя.

Просто собираем один проект в докерконтейнер, нет отличий кроме порта и метода сборки:
```Dockerfile
EXPOSE 8081
CMD ["java", "-jar", "app.jar"]
```

Сохраняем оба образа такими командами в idea
```bash
docker build -t ghcr.io/rocknrollnotdead/cloud-file-storage:latest .
docker push ghcr.io/rocknrollnotdead/cloud-file-storage:latest
```

2. Compose

Собираем сервисы для обоих программ в докер композ файле.
Эти образы будут скачиваться с DockerHub.
Внутри каждого задаются порт(ы), логины и пароли, тома на которых будут храниться данные, иногда другие настройки.
Пароли задаются в формате environment. Ну либо импорт .env файла. 

Потом собираем и сами сервисы.
Туда тоже самое.

Потом nginx и acme-companion для получения сертификата. Там прям стандартно для всех, поэтому копирую это с инета. Главное потом в переменных приложений добавить переменные типа VIRTUAL_HOST



```yaml
services:
  db-1:
    
  db-2:
  redis:
  minio:
    
  app-1:
    image: ghcr.io/rocknrollnotdead/codeportfolio-site:latest
  app-2:
    image: ghcr.io/rocknrollnotdead/cloud-file-storage:latest
    
  nginx-proxy:
  acme-companion:
```

3. Запуск

Дома: `scp docker-compose.yml root@000.000.000.000:~/my_site/`
Также перед заходом на сервер посылаю env файлы по ssh(scp) (в env предварительно закомментировав всё, что было для локального компа), и в докер композе обьявляю файлы, либо беру с них переменные в докер композ файл.
Итого схема файлов на сервере
user/
  program/
    docker-compose.yml
    .env
    spring-app.tar
    tomcat-app.tar
    cloud-file-storage/
      .env


Потом `docker compose up -d` и всё работает.
